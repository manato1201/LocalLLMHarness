# Phase 6(任意): 微調整の準備

設計書の方針: **まず RAG と手順。微調整は、自分の領域の言い回しと形式に限る**(知識を足す目的では、忘却・幻覚が増える恐れ)。
**ここでは、学習は行いません。**データを溜める仕組みと、始めてよい条件を整えました。

## 始めてよい条件(すべて満たすまで、始めない)

1. **評価で、効かせたい区分が負けている**: `llh eval --baseline …` で「Claude に残す」と出た区分があり、それが手順(A1〜A6)の改善でも埋まらない。**負けていない区分には、微調整をしない。**
2. **データが足りている**: `llh export-sft` の書き出しが **300 件以上**(目安。区分ごとに偏らない)。
3. **評価セットが、学習に混ざっていない**: `export-sft` が、評価セット(`evals/cases`)と同じ質問を機械で除外します(`--no-eval-guard` は付けない)。
4. **VRAM に載る見込みを、実測した**: 8GB で現実的なのは、小型(〜9B 級)の QLoRA です。**必要な VRAM は未測定**で、Unsloth Studio の学習画面の見積もり・実際の 1 ステップで確かめます。学習中は、窓口の推論(同じ GPU)を止めます。Houdini の ML 学習・TTS などとも取り合います。
5. **使うデータの利用規約を確認した**: Claude が解いた答えを学習に使う場合は、利用規約を確認します(`--extra` で足す)。

## データの溜め方と書き出し

```toml
# config.toml
[training]
save_verified = true          # 検証に通った生成を、logs/verified.jsonl に保存する(既定は false)
```

- 保存されるのは、**検証つき生成(A1)で検証に通った**ものだけです(`verified_generate` を使う `local_classify` / `local_extract` など)。**質問と回答の全文を含む**ので、ローカルのみ・git に入れません(`logs/` は `.gitignore` 済み)。
- 「外に出さない」区分(秘密・禁止パスを含む)の質問・回答は、**保存しません**(秘密を覚えさせない)。
- 検証に通らなかったものは、内容を残さず、`logs/escalations.jsonl` にハッシュと検証の詳細だけを記録します(A6。次の評価問題を作る材料)。

```powershell
uv run llh export-sft --out logs\sft.jsonl                 # chat 形式(messages)の JSONL
uv run llh export-sft --extra claude_answers.jsonl         # Claude が解いた答えを足す(chat 形式。利用規約を確認のうえ)
```

除外されるもの: 外に出さない区分・評価セットと同じ質問・重複・文字だけでない会話(画像つきなど)。

## 学習(Unsloth Studio の画面で)

1. Unsloth Desktop の **トレーニング** で、`logs\sft.jsonl` をデータセットに指定する(chat 形式)。
2. ベースは、main のモデル(Qwen3.5-9B)。方式は **QLoRA(4bit)**。文脈は 4096 以下から。
3. 学習後は、**同じ評価セットを、必ず再実行**する(`llh eval`)。効果と、**他の区分の悪化**(回帰)を確かめる。悪化したら、使わない。
4. 元のモデルは消さない(`config.toml` で、LoRA 付きのモデルを別の名前で登録して、比べる)。

## やらないこと
- 評価セットの問題・答えを、学習に混ぜない。
- 知識を足す目的の微調整(RAG で足す)。
- 条件 1 を満たす前の学習。
